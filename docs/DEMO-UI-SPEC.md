# Demo implementation direction

The user restored the original canvas idea, selected NVIDIA and NMC², and authorized implementation on November 7, 2026. This supersedes the ideation pause and earlier UI restriction. Product name remains TBD. Northstar Compute is a fictional workspace, not the product name.

## What the demonstration must do

- Show people, services, resources, procedures, tasks, and incidents on a shared infinite canvas with meaningful labeled connections.
- Support pan, zoom, move, add/edit, connect, select, inspect, and an incident-focused view that retains the full graph.
- Accept incident descriptions and contextual messages; show owners, tasks, and exact approval rights separately.
- Use a bounded Nemotron workflow with real scoped tools when a provider key and supported model are available. Label a deterministic scripted backup whenever inference is unavailable or fails. Never invent successful live inference.
- Review an exact fixed disposable-process action, enforce permission in the backend, independently observe its result, then verify fallback prerequisites.
- Show the existing encrypted local-peer relay evidence with its provenance. Ordinary workspace messages must not be described as encrypted mesh transport.

## Visual requirements

Use a light blue-gray canvas, dark ink navigation, cobalt controls, and a small orange accent. Use Avenir Next/system fonts and monospace for technical values. Combine custom game-like SVG icons, squircles, restrained raised/inset surfaces, pixel loaders, decorative flowcharts, and Pretext text measurement/wrapping.

Avoid gradients, gradient headlines, emoji decoration, Inter everywhere, colored card borders, glassmorphism, low contrast, generic three-icon-card layouts, headline badges, stock icon saturation, untouched component presets, scroll fades, cursor beams, fading hover buttons, inconsistent spacing, decorative serif italics, and buzzword taglines.

## Implementation and ownership

Build a loopback-only Node server and plain browser modules for a self-contained local demonstration. The lead coordinates and verifies. Three explicitly GPT-5.6 Sol workers own separate modules: public UI assets; local session/server and package configuration; model adapter plus security review. Keep one writer per module. Avoid unrelated framework migrations and production services.

The fallback is working scripted behavior, not a mock success flag. Real process containment stays limited to the existing broker-owned scheduler. Demo personas are a local demonstration selector, not production authentication. Stores contain fictional plaintext data. Three local peers share one Mac; physical radio mesh remains unverified.

## Model configuration

Store optional provider keys in ignored `.env.local`, never in browser assets or chat. `NVIDIA_API_KEY` enables an attempted live provider run; a supported `NVIDIA_MODEL` and optional trusted `NVIDIA_BASE_URL` may also be needed. A configured key alone is not proof of a successful run. Jev is optional for bounded classification and cannot grant authority. No cloud instance or paid deployment is authorized by this file.
