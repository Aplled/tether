# Flowstate / Graphite reuse audit

**Date:** November 6, 2026\
**Mode:** Read-only repository audit; no dependencies installed, builds run, cloud services called, credentials read, or Flowstate files changed.\
**Decision context:** Response/containment/fallback and mesh are both mandatory. The build window is November 7–8, 2026, 10:00–10:00 Dallas (`America/Chicago`). Inventory is one Mac, possible iOS 27.0.1 iPhone, **no third device**. On November 7 the user accepted three real local peer processes plus an optional phone link, with physical three-device mesh explicitly unverified. Repo findings below remain unchanged.

## Recommendation

Build the cyber-resilience core as a small standalone application rather than taking on Flowstate's whole stack. Use Flowstate as a design reference and selectively reuse isolated helpers only when they reduce work without importing cloud, credential, or UI coupling. This recommendation is about technical fit for 24 hours.

The narrow useful boundary is:

1. Create a minimal operational node/edge contract and deterministic adjacency algorithms in HackUTD. Stable IDs, directed edges, cycle handling, and explanation paths are useful concepts; any copied helper still needs incident-specific correctness review.
2. Reimplement a tiny restart-safe local store for canonical incident state on the Mac. Treat phone storage as a cache and message queue, never as the trusted approval/execution authority.
3. Implement a new, restricted MCP server around the HackUTD application services. Do not reuse Graphite's 43-tool remote surface or its Supabase-backed credential path.
4. Spike the real device transport first because mesh is mandatory and the hardware is uncertain. Keep the Mac as coordinator; the iPhone and any third device exchange authenticated coordination messages but cannot approve or execute infrastructure changes.

There is no reusable mesh implementation in the inspected Flowstate paths. Flowstate supplies a responsive/PWA mobile surface and cloud realtime sync, not an infrastructure-independent peer relay. A Graphite fork would therefore preserve most of its product and security surface while still leaving the mandatory mesh work undone.

## What is genuinely reusable

### Useful concepts and candidate helper boundaries

- The data shape is small and clear: nodes have stable IDs and type-specific JSON, while connections have source, target, direction, label, style, and weight ([`src/types/database.ts:7`](/Users/vyomsingh/Projects/flowstate/src/types/database.ts:7), [`src/types/database.ts:29`](/Users/vyomsingh/Projects/flowstate/src/types/database.ts:29), [`src/types/database.ts:64`](/Users/vyomsingh/Projects/flowstate/src/types/database.ts:64)). This is useful inspiration for an operational graph, but its node vocabulary is productivity-oriented rather than incident-oriented.
- The pure task-chain code demonstrates adjacency maps, deduped directed edges, simple-path recognition, and Kahn ordering ([`src/lib/task-chain.ts:60`](/Users/vyomsingh/Projects/flowstate/src/lib/task-chain.ts:60), [`src/lib/task-chain.ts:183`](/Users/vyomsingh/Projects/flowstate/src/lib/task-chain.ts:183)). These are general algorithm ideas. They are not the required dependency evaluator: the code only gates task-to-task predecessors, treats branches as workflows outside its chain abstraction, and deliberately fails open around cycles ([`src/lib/task-chain.ts:20`](/Users/vyomsingh/Projects/flowstate/src/lib/task-chain.ts:20), [`src/lib/task-chain.ts:46`](/Users/vyomsingh/Projects/flowstate/src/lib/task-chain.ts:46), [`src/lib/task-chain.ts:170`](/Users/vyomsingh/Projects/flowstate/src/lib/task-chain.ts:170)).
- The local cache shows useful defensive patterns: user-namespaced databases, atomic full replacement, tombstone filtering, and explicit handling of unavailable IndexedDB ([`src/lib/local-cache.ts:3`](/Users/vyomsingh/Projects/flowstate/src/lib/local-cache.ts:3), [`src/lib/local-cache.ts:17`](/Users/vyomsingh/Projects/flowstate/src/lib/local-cache.ts:17), [`src/lib/local-cache.ts:20`](/Users/vyomsingh/Projects/flowstate/src/lib/local-cache.ts:20), [`src/lib/local-cache.ts:117`](/Users/vyomsingh/Projects/flowstate/src/lib/local-cache.ts:117)).
- The emergency snapshot separates a user-selected known-good copy from the live cache and distinguishes “empty” from “storage unavailable” ([`src/lib/emergency-backup.ts:3`](/Users/vyomsingh/Projects/flowstate/src/lib/emergency-backup.ts:3), [`src/lib/emergency-backup.ts:36`](/Users/vyomsingh/Projects/flowstate/src/lib/emergency-backup.ts:36)). That distinction maps well to demonstrable recovery.

### What should not be extracted

- The main node store is a large coupled application subsystem: optimistic client state, Supabase persistence, realtime merging, grouping side effects, history, subscription limits, Google Calendar behavior, and UI notifications live in the same path. Even adding an edge can mutate group ancestry and recursively absorb connected chains into a group ([`src/stores/node-store.ts:1869`](/Users/vyomsingh/Projects/flowstate/src/stores/node-store.ts:1869), [`src/stores/node-store.ts:1878`](/Users/vyomsingh/Projects/flowstate/src/stores/node-store.ts:1878), [`src/stores/node-store.ts:1901`](/Users/vyomsingh/Projects/flowstate/src/stores/node-store.ts:1901)). That is drawing/workspace behavior, not operational dependency semantics.
- Graphite edges are generic presentation connections. Direction, label, and weight exist, but there are no hard/optional/alternative/grouped/conditional/unknown dependency contracts, no observed-versus-derived state split, and no deterministic incident explanation model in the inspected core types. Those must be designed for HackUTD.
- The repository's own architecture states that Supabase remains the source of truth and IndexedDB is a best-effort cold-start cache ([`src/lib/local-cache.ts:11`](/Users/vyomsingh/Projects/flowstate/src/lib/local-cache.ts:11), [`src/lib/local-cache.ts:16`](/Users/vyomsingh/Projects/flowstate/src/lib/local-cache.ts:16)). This cannot serve as the trusted local authority when cloud access is disrupted. The HackUTD Mac coordinator needs durable authoritative state, replay protection, and an audit log independent of browser cache success.
- The backup is useful inspiration but is still a single browser-managed snapshot. It does not establish tamper evidence, authorization, event ordering, or independent verification ([`src/lib/emergency-backup.ts:117`](/Users/vyomsingh/Projects/flowstate/src/lib/emergency-backup.ts:117)).

## MCP and authority assessment

Graphite's supported MCP path is a hosted Supabase Edge Function; the local stdio package is explicitly legacy and frozen ([`mcp-server/README.md:1`](/Users/vyomsingh/Projects/flowstate/mcp-server/README.md:1), [`mcp-server/README.md:16`](/Users/vyomsingh/Projects/flowstate/mcp-server/README.md:16)). The hosted endpoint does several good things: it authenticates every request, checks current entitlement, mints a short-lived user token, and runs tool queries under Postgres RLS rather than passing the service client into tools ([`supabase/functions/mcp/index.ts:19`](/Users/vyomsingh/Projects/flowstate/supabase/functions/mcp/index.ts:19), [`supabase/functions/mcp/index.ts:212`](/Users/vyomsingh/Projects/flowstate/supabase/functions/mcp/index.ts:212), [`supabase/functions/mcp/index.ts:245`](/Users/vyomsingh/Projects/flowstate/supabase/functions/mcp/index.ts:245)).

It is still the wrong privilege boundary for this prototype:

- One bearer token exposes both broad reads and writes. The published surface has 43 tools, including cascade deletion and real Google Calendar mutation ([`src/guides/mcp-setup.md:78`](/Users/vyomsingh/Projects/flowstate/src/guides/mcp-setup.md:78), [`src/guides/mcp-setup.md:88`](/Users/vyomsingh/Projects/flowstate/src/guides/mcp-setup.md:88), [`src/guides/mcp-setup.md:155`](/Users/vyomsingh/Projects/flowstate/src/guides/mcp-setup.md:155)). Client-side tool approval is explicitly described as potentially becoming session-wide ([`src/guides/mcp-setup.md:83`](/Users/vyomsingh/Projects/flowstate/src/guides/mcp-setup.md:83)). This is not an exact-action approval capability.
- Workspace and folder deletion use a two-call count confirmation, but the authority remains the agent-held account token and the same general tool endpoint ([`src/guides/mcp-setup.md:173`](/Users/vyomsingh/Projects/flowstate/src/guides/mcp-setup.md:173)). The HackUTD design needs proposal IDs, exact target and parameter hashes, expiry, single use, policy revision, and a separate allowlisted executor.
- Agent writes bypass application enrichment and link logic ([`src/guides/mcp-setup.md:202`](/Users/vyomsingh/Projects/flowstate/src/guides/mcp-setup.md:202)). More broadly, direct table tools are the wrong seam for containment; HackUTD tools should call narrow application services and never expose raw SQL, arbitrary URLs, shell, Docker control, or production credentials.
- The current implementation advertises MCP `2025-06-18` and only accepts three handshake-era revisions ([`supabase/functions/_shared/mcp-tools.ts:89`](/Users/vyomsingh/Projects/flowstate/supabase/functions/_shared/mcp-tools.ts:89)). Its dispatcher still handles `initialize` and `notifications/initialized` ([`supabase/functions/mcp/logic.ts:150`](/Users/vyomsingh/Projects/flowstate/supabase/functions/mcp/logic.ts:150), [`supabase/functions/mcp/logic.ts:196`](/Users/vyomsingh/Projects/flowstate/supabase/functions/mcp/logic.ts:196)). The current MCP `2026-07-28` revision removes that handshake/session model and requires the version and client capabilities per request, plus new routing headers. This is a migration, not a version-string bump. See the [official MCP 2026-07-28 release](https://blog.modelcontextprotocol.io/posts/2026-07-28/) and [TypeScript SDK migration guidance](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28).
- The legacy stdio server reads a long-lived MCP credential from a local `.env` path ([`mcp-server/src/config.ts:6`](/Users/vyomsingh/Projects/flowstate/mcp-server/src/config.ts:6), [`mcp-server/src/config.ts:34`](/Users/vyomsingh/Projects/flowstate/mcp-server/src/config.ts:34)). This audit did not read that file or any credential. Reusing the legacy package would import an obsolete auth flow and a remote Supabase dependency into a demo whose authority should remain local.

Recommended HackUTD MCP boundary: local stdio, read/simulate/submit-proposal tools only, one scoped principal per run, pinned compatible SDK/spec revision, and no infrastructure mutation tool. Exact-action execution belongs to a separate authority API after human approval.

## Mobile and mesh reality

Graphite is documented as a macOS/Windows desktop product backed by Supabase realtime ([`README.md:11`](/Users/vyomsingh/Projects/flowstate/README.md:11)). Its mobile design is primarily a responsive web/PWA shell; the graph/canvas is intentionally excluded on phones ([`docs/specs/mobile-redesign.md:5`](/Users/vyomsingh/Projects/flowstate/docs/specs/mobile-redesign.md:5), [`docs/specs/mobile-redesign.md:28`](/Users/vyomsingh/Projects/flowstate/docs/specs/mobile-redesign.md:28), [`docs/specs/mobile-redesign.md:85`](/Users/vyomsingh/Projects/flowstate/docs/specs/mobile-redesign.md:85)). The plan calls for read-first offline and queued capture through the existing cache-to-Supabase route ([`docs/specs/mobile-redesign.md:460`](/Users/vyomsingh/Projects/flowstate/docs/specs/mobile-redesign.md:460), [`docs/specs/mobile-redesign.md:466`](/Users/vyomsingh/Projects/flowstate/docs/specs/mobile-redesign.md:466)).

The Rust crate has a Tauri mobile entry point and excludes desktop-only plugins on iOS/Android ([`src-tauri/src/lib.rs:542`](/Users/vyomsingh/Projects/flowstate/src-tauri/src/lib.rs:542), [`src-tauri/Cargo.toml:31`](/Users/vyomsingh/Projects/flowstate/src-tauri/Cargo.toml:31)), but the repository evidence does not establish a generated, signed, installed, or tested native iOS target. An iPhone web/PWA test is plausible; a native wrapper is a separate toolchain and signing risk. Tauri's official prerequisites require full Xcode, iOS Rust targets, and CocoaPods ([Tauri mobile prerequisites](https://v2.tauri.app/start/prerequisites/)). Do not make native iOS packaging part of the critical path without proving the toolchain before the build window.

No inspected code supplies peer discovery, local transport, relay routing, message authentication, replay defense, store-and-forward delivery, or multi-device convergence. Supabase realtime is cloud synchronization, and IndexedDB is a per-browser cache. Therefore:

- First hardware gate: prove Mac ↔ iPhone exchange over a real local transport before expanding the backend.
- Call a two-device result a direct authenticated local link with queued delivery. Reserve “mesh” for an authenticated relay across three physical devices, or explicitly label the third participant as a simulated relay if hardware never appears.
- Keep approvals and execution Mac-only. Peer messages may carry evidence, notes, acknowledgements, and proposals; they cannot confer authority.
- Test disconnect, restart, replay, duplicate delivery, modified payload, and stale-message rejection. Record which properties are demonstrated and which remain unproven.

## Repository ownership and license metadata

The root package declares `UNLICENSED` ([`package.json:2`](/Users/vyomsingh/Projects/flowstate/package.json:2)), and the root license is proprietary: it permits viewing and PR-only forks but prohibits use, copying, modification, deployment, and derivatives without prior written permission ([`LICENSE:1`](/Users/vyomsingh/Projects/flowstate/LICENSE:1), [`LICENSE:8`](/Users/vyomsingh/Projects/flowstate/LICENSE:8), [`LICENSE:13`](/Users/vyomsingh/Projects/flowstate/LICENSE:13)). `src-tauri/Cargo.toml` separately says `MIT` ([`src-tauri/Cargo.toml:1`](/Users/vyomsingh/Projects/flowstate/src-tauri/Cargo.toml:1)); that inconsistency is not a safe basis for reuse because the repository-wide license is explicit and the Rust code is only one part of the application.

The root notice names **Vyom**, consistent with the user's presentation of Graphite as their existing project. This audit does not establish a requirement for the user to obtain permission from themselves. Preserve notices and inspect third-party rights for any component actually reused; do not infer that the entire repository is MIT-licensed from Cargo metadata. No source is copied or published during this planning pass. The standalone-core recommendation follows the concrete architectural mismatch above, independently of license metadata.
